# Почему Silero v4_ru/xenia генерирует звук в паузах

Исследование: 10 октября 2026 года. Проверялась установленная модель `v4_ru`,
голос `xenia`, CPU, PyTorch 2.12.0+cpu. Работающий код синтеза в этом исследовании
не менялся. Измерения выполнены до очистки из коммита `42a36f2`.

## Установленная причина

В обоих сообщённых случаях модель предсказывает длинную длительность
неречевого пробела после предлога «В», но акустическая сеть выдаёт для него ненулевой
mel-спектр. Вокодер HiFi-GAN преобразует этот спектр в тихий слышимый звук.
Разметка `word_mask=False` используется для временных меток; сама по себе она
не подавляет акустический выход.

В установленном пакете есть функция `MultiTTSModel.fx_pauses`, которая заменяет
спектр заданной паузы значением `sil_value=-6.5`. Однако `forward` вызывает её
только при непустом словаре `symb_durs`. Для обычного текста словарь пуст:
`process_simple_text` возвращает `break_time=None`, а `merge_batch_model` не
добавляет ограничение длительности. Этот путь включается для явно заданных
пауз SSML. Обычные точки и тире остаются предсказаниями сети, включая её ошибки.

Это вывод из исходного кода внутри проверенного пакета и контролируемых
вмешательств в его промежуточные тензоры, а не утверждение автора Silero
о конкретном дефекте обучения.

## Контроль на «Непобедимом»

Исследован первый запрос фрагмента 4, после слов «из носовой части».
Длительность запроса — 38.175 с. Модель предсказывает пробелу после «В» 52 кадра
по 12.5 мс: 0.650 с, от 3.3625 до 4.0125 с. В книге это примерно
02:48.0625–02:48.7125. Строка с ударениями разделяется на два запроса;
весь фрагмент длится 45.750 с.

Акустическую цепочку удалось собрать отдельно из штатных компонентов модели:
подготовка текста → duration predictor → pitch predictor → акустическая сеть
(`tacotron`) → вокодер. Максимальная разница полученного float-аудио с обычным
`apply_tts` равна **0.0**. Это подтверждает, что исследованы именно исходные
отсчёты модели, до WAV, ffmpeg, кэша и изменения скорости в mpv.

В таблице RMS выражен в масштабе signed 16-bit PCM, до округления. Во всех
строках измеряется один и тот же участок 3.52–3.78 с; вокодер не менялся.

| Контролируемое изменение | RMS в середине паузы |
| --- | ---: |
| Исходная модель | 313.48 |
| Только pitch токена паузы заменён на 0 | 111.89 |
| Только спектр середины паузы заменён на штатный `sil_value` | 1.00 |
| Штатная `fx_pauses` для этого токена, исходная длительность сохранена | 1.00 |

Среднее значение исходного mel-тензора в середине паузы — -1.264, диапазон
-3.259…0.099. Это внутренние признаки модели, не dBFS аудио. Штатное значение
тишины -6.5 даёт примерно 1 PCM RMS. Постоянный такой спектр также даёт примерно
1 PCM RMS при прямом вызове вокодера. Следовательно, слышимый уровень возникает
из предсказанного акустического спектра, а не из заметного собственного шумового
порога вокодера. Обнуление pitch лишь снижает уровень, но не устраняет причину.

## Что исключили сравнением

Для вариантов ниже измерялась середина соответствующей паузы: по 125 мс
с каждого края исключались. Поэтому эти RMS нельзя напрямую сравнивать
с фиксированным окном в предыдущей таблице.

| Вариант | Длительность паузы | RMS |
| --- | ---: | ---: |
| Производственный текст с ударениями, 24 кГц | 0.650 с | 277.13 |
| Точный повтор | 0.650 с | 277.13 |
| Тот же текст, внутренние ударения/ё отключены | 0.688 с | 199.57 |
| Исходный текст без внешней разметки ударений | 0.563 с | 300.91 |
| Только первые два предложения | 0.638 с | 246.41 |
| Производственный текст, 48 кГц | 0.650 с | 307.47 |

Повтор даёт тот же SHA-256. Производственный сырой PCM совпадает с исходным
кэшем. Шум сохраняется без нашего accentor, без внутренней обработки ударений,
при коротком запросе и при 48 кГц. Значит, эти факторы могут менять проявление,
но не являются необходимой причиной. Изменение точки на запятую либо удаление
точки убирает длинную паузу в коротком примере, одновременно меняя интонацию
и длительность речи; это не равно исправлению синтеза исходного текста.

У `kseniya` тоже обнаружены ненулевые неречевые интервалы. Для `aidar` и `baya`
паузы в этом месте короче, но у них также есть ненулевые интервалы в других
местах. Из этой небольшой проверки нельзя заключать, что смена голоса
гарантированно решит проблему.

## Контроль на первом случае с тире

Исходный второй запрос фрагмента 925 в первой книге начинается с тире.
Он длится 8.6125 с; модель предсказывает неречевому пробелу после «В»
паузу 0.1375–1.3000 с. После удаления тире запрос длится 7.4625 с, длинная ведущая
пауза отсутствует.

Отдельная сборка цепочки с отключённым внутренним accentor также по отсчётам
в float совпадает с соответствующим обычным вызовом. Для этого длинного
неречевого токена штатная `fx_pauses`, без изменения длительности, снижает
RMS середины паузы с 65.76 до 0.99. Механизм совпадает со случаем обычной точки.

## Что это означает для исправления

Очистка по разметке модели из `42a36f2` устраняет проявление после вокодера.
Она сохраняет длительность и не вмешивается во внутренние веса. Причину на
уровне генерации можно устранить нормализацией акустических пауз до вокодера
или исправлением/переобучением модели. Замена генератора требует отдельной
проверки качества речи и переходов, поскольку границы разметки приблизительны.

Простая массовая вставка SSML-разрывов не проверена как безопасная замена:
в эксперименте добавление `<break time="650ms"/>` после сохранённой точки
создало тихую явную паузу, но оставило ещё один предсказанный шумный интервал
следом и увеличило длину запроса с 38.175 до 38.800 с.

Не установлено, почему именно веса акустической сети научились такому спектру:
дыхание/фон в обучающих записях, особенности функции потерь и обработки пауз
остаются гипотезами. Для их проверки нужны обучающие данные и методика Silero.
Мы установили механизм на этапе вывода, а не происхождение ошибки обучения.

## Источники и материалы

- Проверенный локальный пакет `v4_ru`: `multi_acc_v3_package.py`,
  `__torch__/silero_vocoder/jit_model.py`, `__torch__/jit_forward_model.py`,
  `__torch__/vocoder/hifigan/jit_vocoder.py`.
- [Официальная документация SSML](https://github.com/snakers4/silero-models/wiki/SSML):
  API явно заданных пауз через `ssml_text` и `<break>`.
- [Историческое обсуждение шума v2](https://github.com/snakers4/silero-models/discussions/93):
  автор описывает другой дефект, связанный с батчами и шумом в конце записи.
  Его нельзя считать объяснением нашего v4-случая: здесь один запрос, шум
  внутри записи, а акустическая цепочка воспроизводится напрямую.

Локальные воспроизводители и численные результаты находятся в
`/tmp/tts-silero-rootcause/`: `variants.py`, `components.py`, `ssml_and_dash.py`,
соответствующие логи, `variants.json`, `components.json`, исходные float-аудио
и промежуточные тензоры. Файлы из `/tmp` не входят в репозиторий.

## Уточнение при реализации адаптера

Сопоставление ID токенов с их символами показало, что в двух воспроизводителях
длинная пауза назначена пробелу после «В» (ID 46), а не самой точке/тире.
В первом запросе фрагмента 4 это индекс 72; буква «В» находится на индексе 71,
точка — на 69. Во втором запросе фрагмента 925 пробел находится на индексе 4.
Начальное тире преобразуется моделью в `=`. Поэтому отбор только пунктуационных
ID пропускает оба случая; необходимо обрабатывать длинные пробельные паузы тоже.
Основной вывод о ненулевом спектре, проверка вокодера и результаты `fx_pauses`
сохраняются. Предыдущее описание конкретного токена как точки/тире было неточным
и исправлено выше. Пунктуация влияет на предсказание пауз через контекст.

Новый адаптер `tts_silero.py` реализует исправление до вокодера. Старые PCM-фильтры
и удаление начального тире удалены. Исторические эксперименты выше сохраняются
как обоснование механизма и не описывают действующий способ обработки.
